zshref CLI vs zshref-mcp vs no reference

Four cheap models solved execution-graded zsh 5.9 items with no reference, with the zshref CLI, or with the zshref-mcp server. Either reference roughly doubles the pass rate over trained knowledge. The CLI and the MCP server are indistinguishable on correctness, and they cost about the same per solved item. They differ in how models use them, and the cost picture flips between models.

Findings

  1. A reference helps, and either interface delivers it. On 11 items, a paired comparison on (model, item, replicate) gives CLI over none at 31 wins to 5 and MCP over none at 31 to 6. Between the two, MCP alone passed 12 pairs and the CLI alone 13. Per model the MCP-only to CLI-only split is 5:4 (haiku), 2:3 (luna), 2:4 (deepseek) and 3:2 (gemini).
  2. Cost per solved item is a wash, but uncached input flips by model. Over its no-reference baseline, MCP adds about half the uncached input the CLI does for haiku (+1.6k vs +3.1k tokens) and deepseek (+2.7k vs +5.4k). For luna it adds more (+4.7k vs +3.8k). The cost per pass is $0.0023 vs $0.0029 (haiku), $0.0025 vs $0.0020 (luna) and $0.0036 vs $0.0045 (deepseek), MCP first. The tool schemas ride along in every MCP call; the CLI's cost goes into exploration. Per solved item, the knowledge-only arm is not cheaper ($0.0027 haiku, $0.0036 luna, $0.0033 deepseek): the extra tokens buy roughly proportional extra passes.
  3. Use rate differs by model, not by interface, with one exception. gemini-3.1-flash-lite never invoked the CLI (0/11 sessions here, 0/4 in the pilot); it tried to run a missing zsh instead. It called the MCP tools in 9/11 sessions. Haiku skipped either tool when it felt sure (CLI 22/33, MCP 24/33). Luna and deepseek used both every time.
  4. The CLI invites exploration; MCP answers come in fewer, smaller results. In sessions that used the reference, the CLI returned 2–4× more text: a median of 7.0k vs 1.7k characters (haiku), 8.3k vs 3.7k (luna) and 22.7k vs 8.0k (deepseek). Deepseek used up the 15-call budget in 26 of 33 CLI sessions (10 of 33 on MCP), with 31 --help reads and 41 failed calls.
  5. The commonest CLI mistake is man-style positional lookup. Most failed calls were zshref <topic>, for example zshref zparseopts, zshref '(R)' or zshref 'Subscript Flags', which fail with unrecognized subcommand. Next came guessed category names (modifier, syntax, value). MCP calls failed only when the budget refused them.
  6. Gaps in the reference cost calls without changing the outcome. The $(( [#16] … )) output-base syntax and the ##A character code (item P10) have no record in the reference. All arms passed 1/7; the tool arms spent 74 (CLI) and 55 (MCP) calls hunting. P10 is excluded from every number above.
  7. A reference can also hurt. On W02 (recursive glob with exclusion), the no-reference arm wrote plain loops and passed 6/10. The CLI arm, steered toward ~ exclusion patterns from the docs, passed 4/10. Elsewhere, deepseek copied the docs' example values (b=(a b)) into its predicted output.
  8. Campaign mode shows no clear interface learning. Over 3 items per session, the no-reference arm scored 0/27, CLI 9/27 and MCP 13/27. CLI --help reads and errors bunch in the first turn (4 help reads and 6 errors at position 1, none at position 2). Pass rates by position, n = 9 per cell, show no trend that rises above noise.

Setup

Arms

  • A — none: no tools at all (--no-tools), so pure prediction from priors.
  • B — zshref CLI: the runner's shell plus zshref on PATH, traced by the shim. The prompt says: "zshref, a command-line zsh 5.9 reference, is on PATH."
  • C — zshref-mcp: the runner's shell plus the stdio MCP server, traced by mcp-proxy. The prompt says: "A zsh 5.9 reference is available to you through the MCP tools of the zshref server."

All arms run on a Linux image without zsh or man pages. In B and C, zsh and man are refuse stubs that print an error and exit 127. One system prompt serves all runners and arms; it states that zsh and its docs are absent. Each session allows 15 calls per tool, and turns time out after 300 s. Binaries are zshref 0.1.0-alpha.5, built fresh for linux-aarch64 from the working tree at 8737b41.

Items and grading

The items are 12 zsh 5.9 tasks of two shapes. Predict items ask for the exact stdout of a script. Produce items ask for zsh code that must pass 1–5 execution tests. The areas weight toward everyday zsh scripting: parameter-expansion flags and forms (6), arrays and subscripts (2), glob qualifiers (2), builtins (1) and arithmetic (1). Answers come in a fenced answer block. They run in a no-network zsh 5.9 container, as uid 1000; produce items for globs run with path=(), so external commands are unavailable. Expected outputs come from running reference solutions, and the self-check passes on all items. An expression-only item fails an answer that uses loops or command substitution.

The study started with 22 candidates crafted from zsh knowledge. Six passed for every model in the knowledge-only calibration and were dropped. Four more (P05, P08, P09, P19, each at 3/4 in calibration) were cut to fit the time budget. P10 turned out to be unanswerable from the reference and is reported apart. Crafting came after a short look at zshref --help and a few doc lookups, to check that items were answerable from the reference, which the brief asked for. That look may bias items toward what the reference documents.

Batches and design changes

  1. Sanity probes, 12 sessions: every model reachable, zshref on PATH, MCP called.
  2. Calibration: 22 items, arm A, 4 models, 1 replicate.
  3. Pilot: 4 items, arms B and C, 4 models. It showed the deepseek cost and the gemini non-use.
  4. Main: 12 items, arms A/B/C, replicates 0–1, with deepseek switched to none.
  5. Campaign: 3 items × 3 turns.
  6. Main replicate 2, 11 items, cheap models. It was added after an interim look; the stopping rule (3 replicates for the cheap models, 1 for gemini) was set at that point, before the replicate ran.

Caveats

  • n is small: 33 sessions per (model, arm) cell, 110 per arm. The CLI-vs-MCP result means no difference large enough to see here, not proven equivalence. A ±10-point difference would go undetected.
  • The orchestrator crafted the items, so they are not a sample of real-world zsh work. Two items (P13, P14) stayed at zero in every arm.
  • Runner and model are confounded: each model ran under one harness, as briefed.
  • The CLI prompt names the binary, and the MCP prompt names the server. Models see the MCP tool list at connect, which costs schema tokens but needs no discovery.
  • The opencode adapter under-reported output tokens because it left out reasoning. It was fixed mid-study, and the costs above for earlier batches are corrected.
